# 骨架图动作正确性：方法论

> 起因：2026-10-14 用户指出俯卧撑底部前臂弯得太厉害。实测底部前臂偏离竖直 63°（2D）/ 57°（3D），
> 跪姿俯卧撑 46° / 44°。而全套 255 条断言是全绿的。

## 1. 为什么会发生

**断言只管「自洽」，不管「对」。** 现有校验管的是几何自洽：骨长、贴地、身体一条线、两帧支点不漂、
不越框、不穿头。这些都对，但它们只能证明「画出来的东西是一副合法的骨架」，证明不了「这是正确的动作」。
动作是否正确，只有卡片 cue 明文写出、并被翻译成断言的那几条才受约束（杠过足中线、髋低于膝……）。

**误差流向没有被约束的自由度。** 俯卧撑这里同时有四条硬约束：手钉在地上、脚尖钉在地上、
身体是一条直线、骨长固定。构造姿态时又加了一条来自文字的「手在肩正下方」。
身体绕脚尖转，到底肩只前移约 10px，手几乎还在肩下——上臂 50px 没处放，
求解器只能把它甩到唯一没人管的方向：肘往脚的方向倒，前臂随之斜 63°。
**每条约束都满足了，错误被挤进了没有断言的那个关节。**

**错误的源头在文字里。** 安全提示写的是「手掌在肩的正下方略外」——这是顶部的手位，
而 cue 没写底部前臂应竖直。姿态按文字构造，文字缺一条，图就缺一条；文字有偏差，图就照着偏。

**3D 层原样继承。** 环绕视角的手臂按「2D 画出来的肘方向」求解，2D 错，3D 跟着错。
卧推有 `foreVertical`，俯卧撑没有——同一个判据只在一个动作族里被翻译成了代码。

## 2. 怎么解决的（一个错误的标准处理流程）

1. **查资料定判据**：至少一个权威来源（ACE / NSCA / ExRx / 主流教练教程），写成可量化的几何条件。
   俯卧撑：底部侧视前臂竖直（肘在腕正上方），肘与躯干约 45°。
2. **找冲突**：把新判据和现有约束一起列出来，看是否可同时满足。俯卧撑里「顶部手在肩正下方」和
   「底部前臂竖直」在刚体绕脚尖转的前提下**不可兼得**——只能放弃前者，手挪到下胸下方，顶部手臂后倾约 20°。
   完全竖直的前臂配 40° 外展又要两倍肩宽的手距，于是允许正面看前臂外倾 15°（`foreTilt`）。
3. **按约束构造坐标，不手摆**：从固定点（脚尖、手）、骨长和判据反解关节坐标（脚本见提交记录），
   使归一化是恒等变换。
4. **3D 用判据求解**，不沿用 2D 方向：`foreVertical` 直接把 IK 的 pole 指向「手正上方一个前臂长」的点。
5. **改文字**：cue / setup / self_check 与图同步，否则图和字互相打架。
6. **加断言**：新判据写成测试，量的是渲染用的 3D 关节（`tests/orbit.test.mjs`），同时查 2D 数据本身。
   断言要能在旧坐标上失败。
7. **回归**：受影响的共享代码（`foreOffset` 的符号）用改前改后的卧推坐标逐帧对比，确认不变。
8. **独立评审**：figure-reviewer 用坐标与渲染产物核实，再跑全量测试（不并发）。
   俯卧撑第一轮评审挡下了两处**修复本身引入的回归**，现有断言都没抓到：
   - 手在地上来回滑 8–11px：补间按两段极角插值，两端投影长度不同时手的 x 会漂，而断言只查 y。
     → 第二支点要同时钉 x 和 y，肘用 IK 解（`interp.mjs`）。
   - 原始坐标的臂长与登记的类别不符，归一化把整个人抬高 2.4px，跪姿的膝全程离地。
     → 构造坐标后要断言「归一化是恒等」。

   **教训：改一个关节的约束，要把它在补间、归一化、3D 三层里各自的路径都查一遍。**

## 3. 怎么系统性地查出更多同类错误

### 3.1 先找「没人管的关节」

对每个动作，列出它的关节 × 阶段（起始 / 底部 / 中段），标出哪些量有断言约束。**没有断言的量就是
误差的去处**，优先审计。典型高危量：

| 量 | 常见判据（需逐条查资料确认） | 涉及动作 |
|---|---|---|
| 前臂与竖直夹角 | 推类底部前臂竖直；划船、下拉终点前臂与拉力方向一致 | 卧推、俯卧撑、推举、划船、下拉、引体 |
| 小腿与竖直夹角 | 硬拉起始小腿近竖直；深蹲膝可过脚尖 | 硬拉、RDL、深蹲、分腿蹲 |
| 躯干与地面夹角 | 低杠比高杠更前倾；划船躯干约 45° 或更平 | 深蹲、划船、早安 |
| 上臂与躯干夹角 | 卧推 / 俯卧撑肘约 45°；弯举上臂贴体不动 | 推类、弯举、下压 |
| 关节活动终点 | 锁定是否伸直、底部是否到位（ROM） | 全部 |
| 负荷与支撑的相对位置 | 杠过足中线、手在杠正下方 | 杠铃类 |

### 3.2 跑一份关节角报表，和资料范围对表

用脚本对每个动作在 u=0、0.5、1 取 3D 关节（`orbitLift`），输出上表各量。
逐动作对照资料给出的范围，**偏离超过约 15° 的标出来**，再逐条查资料确认是不是错误
（有些偏离是动作本身的变式，要有来源才能改）。

### 3.3 文字与图对账

逐条读 cue / setup / self_check / mistakes，每一句里凡是能落到几何上的（「肘在腕上方」「小腿竖直」
「躯干前倾 45°」「手在肩下」），去图上量。两类问题都要修：图违背了文字；文字本身与资料不符
（俯卧撑就是后者）。

### 3.4 约束冲突检查

一个姿态如果需要很「别扭」的关节角才能满足所有约束（像俯卧撑的肘），往往是某条约束本身错了。
报表里任何一个角度落在两端极值附近，都要回头查是哪条约束把它逼过去的。

### 3.5 修复的准入门槛

- 必须有资料佐证（写进提交信息与下表）；凭感觉不改。
- 必须加一条会在旧坐标上失败的断言。
- 必须全量测试通过 + figure-reviewer APPROVE。
