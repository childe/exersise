## 一、受控字段的机器校验（确定性闸门）

§9.3 第 11 条里能被确定性判定的部分，已经落成代码；下面每一条都有对应的校验器与测试，
改坏会让 `node --test tests/` 与 `node src/build.mjs` 直接失败，而不是等人去发现：

| 检查项 | 实现 | 覆盖范围 |
|---|---|---|
| (a) 自检判据不得要求在负重状态下改变握持／支撑 | `src/validate/exercises.mjs`（`self_checks[].how` 命中「松开一只手／单手／负重下改变握」即报错） | 全部 55 张动作卡 |
| (b) 每个动作都写明失败退出方式 | `safety.bailout` 必填；`solo_ok=false` 必须给出 `solo_alt` 且该 slug 必须在库内 | 全部 55 张动作卡 |
| (c) 自检判据必须写明边界 | `self_checks[].cannot` 必填（"这条判不了什么"） | 全部 55 张动作卡，共 110 条判据 |
| (d) 全站不存在"不上卡扣"的建议 | `safety.collars` 受控：命中 `(不上\|免\|不用\|无需\|可不)\s*卡扣` 即报错；导读另有专项测试 `tests/ch0.test.mjs` | 全部杠铃动作 + 导读 |
| (d) 会把人压住的动作写明前置条件与替代动作 | `barbell-bench-press`、`close-grip-bench-press` 的 `solo_ok=false` + `solo_alt`（分别指向 `db-bench-press`、`cable-pushdown`）；导读第 ④ 条写死杠铃卧推的硬性前置条件 | 杠铃卧推类 |
| (e) 疼痛不并入疲劳调整规则 | 模板 `failure_rules` 出现「疼痛／痛」即报错（字段 8 只处理疲劳）；`pain_path` 必须是安全口径 C1 的受控引用（`canon:C1` 或 C1 全句逐字一致）；`substitutions[].scope` 必须声明"不适用于疼痛" | 全部 5 套模板 |
| 口径单点控制 | `docs/safety-canon.md` → `src/safety-canon.mjs`，C1–C5 缺任一小节即构建失败 | 全站 |

**为什么把这些做成受控字段而不是关键词扫描**：C1 原句本身含"疼痛不走 deload、不走减量"，
任何关键词正则都会把正确答案判成违规（计划里已用 Node 实测过）。受控字段比对的是取值，
不存在否定语境问题。

逐卡的 (a)–(e) 五列明细不再在本文件里重抄一遍——它等价于
`node --test tests/exercises.test.mjs tests/plans.test.mjs tests/ch0.test.mjs` 的通过结果，
而那个结果每次构建都会被重新验证一次，比一张会过期的表更可靠。
2026-10-12 的执行结果：**123 项测试全部通过**。
